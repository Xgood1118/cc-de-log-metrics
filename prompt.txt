在现有 logm 骨架上，把它做成一个能处理多种日志格式、按事件时间滚动聚合的指标引擎。保留现有函数名，只用 Python 标准库，不得引入第三方依赖，不得改动三个日志文件。

## 需要完成

1. **多格式解析**
   - 、access.log 的 nginx combined 格式：注意有的行把请求写成了 `"GET /a 200 12"` 这种被截断的形态，状态码要取引号外那个真实字段。
   - app.jsonl 是 JSON Lines，时间戳是带时区的 ISO 8601，要统一转成 UTC。
   - syslog.log 是传统 syslog，月份是英文缩写，没有年份（按配置给的基准年份补全）。
   - 解析失败的行不能静默丢弃，要按格式统计 unparsed 数并给出前几行原文。

2. **事件时间与水位线**
   - 聚合必须用事件时间，不能用文件顺序。
   - app.jsonl 里有迟到 30 秒的记录和乱序记录，要正确处理：记录进入对应窗口，超过允许迟到（默认 30 秒）的划为 too_late 并单独计数。
   - 窗口类型支持滚动（固定长度）与滑动（长度+步长），窗口长度从命令行传入，例如 1m、5m。

3. **指标**
   - 每个窗口输出：请求数、按状态码分类计数、错误率（5xx/总数）、独立 IP 数（按 /24 归一）、Top N 路径。
   - 支持按文件里出现的所有格式合并统计，输出时标明来源格式。

4. **输出**
   - 输出 JSON：窗口列表（按窗口起点排序）、每个格式的 unparsed 统计、too_late 统计。
   - 退出码：全部解析成功 0，存在 unparsed 行 1，参数错误 2。

5. **测试**
   - 覆盖三种格式解析、ISO 时间转 UTC、乱序与迟到判定、滚动与滑动窗口边界、错误率计算。
   - `python -m pytest tests -q` 全部通过。
